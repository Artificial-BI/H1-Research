# 3D Visualization: схема, построенная из вычисленных FLRW-кадров

Вкладка **3D Visualization** использует вычисленные данные существующего FLRW-интегратора или существующий модуль корней Experiment 32. Она не добавляет уравнений к физическому backend.

> **СХЕМАТИЧЕСКАЯ ВИЗУАЛИЗАЦИЯ — не буквальный объём, граница или вложение Вселенной.** Сетка, сферы, цвета и прозрачность — только средство отображения координат.

## Режимы

### FLRW expansion

Используется текущая кривая главного окна, включая его параметры и диапазон интегрирования. Время `t` — дочернее собственное время относительно `t₀=0` при `a=1`; показываются `a`, вычисленные `H(a)`, redshift `z` и ускорение, из которого получается `Hdot`. Отображаемый радиус монотонно изменяется с `a` по лог-нормированной шкале от 0.18 до 2.4 условных единиц, чтобы ранние эпохи оставались видимыми. Эта шкала не физическая длина и не размер Вселенной.

### FLRW bounce / Experiment 32

Выберите один из существующих пресетов Experiment 32. Анимация доступна только когда найден корень с `a_b>0` и `Hdot(a_b)>0`. Траектория идёт по разрешённой большой-a ветви: сжатие `H<0` → минимальный `a_b` при `H=0` → расширение `H>0`. Для регуляризации в корне численно интегрируется `dt/du`, где `u=sqrt(a−a_b)`; деления на ноль `H` нет. Кадры с `F=H²<0` не создаются. Компаньон-график показывает `H²(a)`, нулевую линию и запрещённые интервалы.

Плоские пресеты не имеют bounce, поэтому для них панель сообщает об отсутствии траектории вместо имитации движения. Для закрытого демонстрационного Lambda-набора bounce находится около `a_b=0.6464534366`; меньший корень около `0.2571947827` — turnaround, а между корнями находится запрещённый диапазон. Bounce проходит на отдельной допустимой ветви большого `a`.

## Управление и времена

- **Mode** переключает FLRW expansion и bounce.
- **Model** выбирает пресет Experiment 32 и доступен в bounce-режиме.
- Ползунок перемещает текущий вычисленный кадр. **Play/Pause**, **Step**, **Reset timeline** и скорость управляют воспроизведением через Qt-таймер.
- В OpenGL-сцене вращение выполняется мышью, перемещение камеры — перетаскиванием правой/средней кнопкой, zoom — колесом. **Reset camera** возвращает начальный вид. `Coordinate grid` переключает опорную плоскость.
- `K0`, пара daughter/parent единиц и `K(a)` выбирают явную гипотезу отображения. Кнопка H1 задаёт иллюстративный `10⁹ yr/s`. При включённом parent-time показывается `T−T₀` в выбранной единице с подписью закона `K(a)`.
- `t` и `T` — разные координаты и единицы; `T` не выведено из ОТО. Изменение `K0` не меняет `a`, `H` или дочернюю траекторию.
- `Epoch labels` включает числовую подпись выбранного кадра.

В FLRW expansion якобиан родительского времени интегрируется существующим `integrate_mapping`. В bounce-режиме `dT/dt` интегрируется по выбранному отображению относительно нуля в bounce; это координатная гипотеза, не родительская собственная метрика.

## Установка и ограничения

Запуск Windows 10/11 из корня проекта:

```powershell
uv sync --extra dev --extra visualization-3d
uv run h1-simulation-lab
uv run pytest
```

OpenGL backend использует PyQtGraph `GLViewWidget` и необязательный PyOpenGL. Без него вкладка остаётся безопасной: показывается сообщение, а независимые вычисления кадров и 2D companion plot доступны. Реальная доступность аппаратного OpenGL зависит от драйвера Windows, Qt-сборки и удалённого/виртуального дисплея. Перед установкой extra команда `uv sync` может скачать PyOpenGL в локальное окружение проекта; системный Python не меняется.

Графический объект ограничен сеткой 5×5×5 (без центрального маркера), 21 проволочной линией, тремя осями и максимум 1201 кадром. Эта сцена не моделирует галактики, звездообразование, гравитацию как резиновый лист, родительскую геометрию, метрики/каузальные диаграммы, рождение вселенной или 3D ОТО. Кривизностная сетка и механизмы рождения — следующие отдельные этапы, здесь не реализованы. Никакие эпохи формирования структур не синтезируются.

Успешная отрисовка/численная проверка подтверждает только работу выбранного алгоритма и его отображения, а не физическую гипотезу H1. Скриншот или ручная проверка desktop должны указываться только после их фактического выполнения.
