# H1 v0.2 — от реестра к проверяемой математической модели

**Режим:** планирование после read-only registry. Никакие новые вычисления, solver или GUI в этой работе не создаются. Старые исходники, результаты и navigation сохраняются как архивный reference.

## Gate 0 — фиксировать словарь без смешивания моделей

Перед моделированием каждая величина должна иметь определение и область действия из [registry](h1-v0.2-mathematical-registry.md). Для каждой записи отдельно хранить: уравнение; действие/источник; gauge; assumptions; численную проверку; независимую физическую проверку; неизвестное.

Статусы `VERIFIED_WITHIN_ORIGINAL_MODEL`, `CONDITIONAL_TRANSFER`, `NOT_DERIVED` — не шкала доказанности H1. В частности, формульная проверка shell не переносится на FLRW, а scalar constraint на начальном срезе не означает совместную эволюцию.

## Gate 1 — выбрать ОДНУ минимальную self-consistent теорию

До solver необходимо написать одну action и получить из неё:

1. динамические поля и независимые метрики/связности, signature и единицы;
2. стресс-тензоры каждого сектора и все interaction terms;
3. уравнения Эйнштейна/обобщённой гравитации, matter equations и Bianchi/conservation identities по каждому сектору;
4. гиперболическую/характеристическую структуру: causal cones, null directions, начальную Cauchy data и constraints;
5. смысл bounce: какие инварианты конечны и какое условие на `Hdot`, expansion, плотность и null congruences определяет переход;
6. физическую структуру branching: manifold/atlas, shell или гладкая переходная область, boundary/matching terms и что именно называется родителем/дочерью;
7. физически определённых наблюдателей/мировых линий для любых часов или сигналов между секторами.

### Кандидаты для теоретического сравнения (не объединять в hybrid)

| Кандидат | Возможный ответ | Жёсткий критерий остановки |
|---|---|---|
| 4D GR + канонический скаляр + false-vacuum potential | Конкретная классическая bubble, shell limit, stress/NEC и локальная dynamical formation question | Если цель требует плоский nonsingular canonical bounce, `Hdot≤0` запрещает этот элемент; Farhi–Guth препятствие применимо лишь при своих условиях пузыря/AF/NEC/critical growth. Не объявлять общего no-go. |
| Einstein–Cartan gravity + spin matter | Тестировать, может ли torsion/spin density в одном фиксированном действии разрешить bounce | До определения action, spin current и микрофизического усреднения нельзя импортировать effective `ρ(a)` или считать bounce физически полученным. |
| Higher-dimensional shared bulk / brane coupling | Явно дать общую gravity sector, отдельно локальные brane matter fields и проверить передачу геометрического, но не обычного matter сигнала | Если нет конкретного bulk/brane action, junction conditions, well-posed IVP и finite conserved flux, лозунг «общая гравитация» не становится моделью. |

Эти кандидаты ортогональны. Bimetric/multimetric interaction — возможный четвёртый вариант, только после отдельной проверки constraint structure и допустимости interaction potential; он не является стандартной ОТО с двумя одинаковыми решениями.

## Gate 2 — математическая допустимость и no-go audit

Для выбранного действия до численного прогона:

- решить гамильтоново и импульсное ограничения на регулярном parent-only срезе с чётко описанными концами и asymptotics;
- проверить NEC/ANEC или заменяющее условие, null focusing, energy flux и граничные члены;
- сопоставить только теоремы, чьи assumptions действительно выполнены. Для Farhi–Guth нужно отдельно проверить тип bubble, AF родителя, классическую эволюцию, null energy и critical-size condition; Penrose требует appropriate trapped surface, global hyperbolicity и null convergence; BGV — кинематическое условие усреднённого расширения по past-directed геодезической;
- если теорема запрещает конкретный вариант, оставить результат как conditional no-go и описать, какое допущение нарушается в другой теории. Не объявлять loophole работоспособной без собственной модели.

## Gate 3 — pre-register независимые фальсификационные проверки

До реализации задать test matrix и количественные pass/fail:

1. vacuum/analytic solution и точный zero-amplitude limit;
2. слабополевой режим против аналитического решения/независимого formulation с физически сопоставимыми initial data;
3. минимум три пространственных resolution, отдельная temporal refinement, сходимость независимых Hamiltonian/momentum, curvature, mass/energy flux и center regularity;
4. фиксированный finite boundary, движение boundary до causal contact и затем nonzero outgoing flux;
5. промежуточная и сильная затравки, gauge-stop/regularity критерии заранее объявлены;
6. причинная проверка: null rays на вычисленной метрике, trapped vs apparent vs event horizons, causal past/future заданного родительского observer/infinity; глобальное утверждение только при полной геометрии/достаточном future extension;
7. отрицательный control: configuration, где proposed bounce/branching/coupling должен отсутствовать.

Кодовый PASS не равен подтверждению действия. При росте ограничения или неустойчивом порядке — STOP физической интерпретации, а не post-hoc изменение порога.

## Gate 4 — проверить clocks, не переобозначать координаты

| Обозначение | Значение | Когда допустимо сравнение |
|---|---|---|
| `mu*t` | Безразмерное coordinate time классического scalar solver | Только внутри определённой gauge/domain постановки. Не родительские секунды. |
| `tau(r)=∫alpha(t,r)dt` | Proper time фиксированного `r` observer для polar zero-shift метрики | Сравнивать только после задания физически сопоставимого observer/worldline. |
| `tau_B` | Proper time shell observer из Israel model | Только на shell; не автоматически FLRW cosmic time. |
| `t_D` | Cosmic proper time comoving observer homogeneous daughter FLRW | Требует реально полученной/заданной daughter FLRW metric. |
| `T_P` | Proper time конкретного parent observer | Требует parent metric, worldline и, для cross-level law, механизма связи событий. |
| `(u,v)` | Null coordinates одного spacetime | Не часовое отображение, а координаты вдоль null characteristics. |

Формула `dt_D/dT_P=K0 a_D^n` останется **NOT_DERIVED**, пока action/matching не выведет её и не задаст observer mapping. `K0=10⁹ daughter yr / parent s` — только условная метка. Нельзя подменять `a_D` радиусом shell, `phi`-threshold, lapse, `Ω`, `mu*t` или conformal factor.

## Gate 5 — только затем проектировать solver_H1

Если Gate 1–4 прошли, выбирать численные переменные, gauge и outer/center boundary по выведенному действию. Минимальный solver должен документировать constraints/evolution, сохранить independent diagnostics и reproductions, уметь сообщать `GAUGE STOP / UNKNOWN GLOBAL`, и выводить machine-readable параметрический provenance. Старый GUI и старые backend-ы не переименовывать в solver_H1 и не подменять ими новый physical model.

Критерий первой допустимой solver версии — не красивый рисунок/успешная траектория, а constraint-consistent Cauchy data, согласованные equations, независимые convergence и causal-domain report. Даже тогда separate daughter universe требует отдельного globally defined construction.

## Текущий статус и единственный ближайший полезный шаг

| Вопрос | Статус сейчас |
|---|---|
| Локальная FLRW bounce | Только заданный closed `Λ` пример #32; ветви разделены `F<0`; не formation. |
| Israel shell | Локальная vacuum dS/Schwarzschild сшивка; не получена из parent-only data. |
| Smooth coupled formation | #40–#41F и отчёт о тестах коллапса–отчёт о double-null проверке численно не валидированы для backreaction; global causal outcome неизвестен. |
| Common gravity interaction | Нет inter-metric action/transfer law. |
| Cross-universe time | `NOT_DERIVED / NOT_COMPARABLE`. |
| Повторные рождения BH / обычный matter transfer | Не постулаты модели и не ограничены расчётами. |
| H2 | Отдельно; не использовать как объяснение H1 в этом плане. |

**Одна рекомендуемая следующая теоретическая работа:** составить сравнительную записку уровня действия для ровно трёх отдельных вариантов: (i) GR+canonical false-vacuum scalar, (ii) Einstein–Cartan+spin source, (iii) explicit shared-bulk/brane gravity. Для каждого выписать action, stress/constraints, возможный bounce criterion, causal structure required, clock observables, theorem assumptions и безусловные причины STOP. Выбрать не более одного только если он проходит эти gates. Не начинать кодирование в рамках этого документа.
